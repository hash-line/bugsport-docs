## Outcome

You will validate a first issue through the BugsPort REST contract without creating it.

## Prerequisites

Get the project ID and project API key from project settings. For mobile ingestion, use the project-scoped `x-api-key` header; do not substitute a logged-in session credential.

## Configuration

The contract publishes a relative request path, not a public production host. Set `BUGSPORT_BASE_URL` to the BugsPort environment you operate, then use this endpoint:

```http
POST /v1/projects/{projectId}/issues
x-api-key: YOUR_PROJECT_API_KEY
Content-Type: application/json
```

The current contract declares `http://localhost:4000` as a local-development server. It is not a production API host. Do not hand-edit generated endpoint pages; update the snapshot from a clean BugsPort checkout with `pnpm sync:openapi` and regenerate them instead.

## Send an issue

Use `validateOnly=true` first. The body must be a non-empty JSON Patch array. Each operation uses only `add`, `remove`, `replace`, or `test`, includes an `op` and `path`, and targets a server-supported path: `/fields/...`, `/relations/...`, or `/rev` for a revision test.

```bash
curl --request POST \
  "${BUGSPORT_BASE_URL}/v1/projects/YOUR_PROJECT_ID/issues?validateOnly=true" \
  --header "x-api-key: YOUR_PROJECT_API_KEY" \
  --header "Content-Type: application/json" \
  --data '[
    {
      "op": "add",
      "path": "/fields/title",
      "value": "BugsPort documentation verification"
    }
  ]'
```

## Verify in BugsPort

The contract returns `200` when `validateOnly=true` validates. When the payload is ready to create an issue, repeat the request without `validateOnly=true`; the creation response is `201`.

For the ingestion operation, see [Create project issue](/api/reference/v1/projects/projectid/issues/post). Browse the generated [endpoint reference](/api/reference/v1/health/get) for the rest of the contract.

## Troubleshooting

Confirm the relative path, project ID, `x-api-key`, and non-empty supported JSON Patch body. See [troubleshooting](/product/troubleshooting) for more help.
