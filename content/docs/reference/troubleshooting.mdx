## REST validation fails

Use the relative `POST /v1/projects/{projectId}/issues` route for the BugsPort environment you operate. Confirm that the request sends the selected project ID, a project-scoped `x-api-key`, and a non-empty JSON Patch body with a supported path such as `/fields/title`. Start with `validateOnly=true`.

## Android cannot send a first issue

The released Android package is pre-alpha and does not expose a completed public app-facing first-issue method. Confirm API 24+, JDK 21, the project ID, and the API key, then use the [REST validation request](/docs/platforms/rest-api). See [Android configuration](/docs/reference/android-configuration) for the supported package boundary.

## iOS package resolves but no initializer is available

The released pre-alpha XCFramework does not export the source-sample initializer or its configuration type. Keep the integration at the verified package-resolution boundary and use the [REST validation request](/docs/platforms/rest-api). See [iOS configuration](/docs/reference/ios-configuration) for the release limitation.

## Flutter setup is requested

Flutter is coming soon and has no released dependency or initialization API. Use the [REST API guide](/docs/platforms/rest-api) until a package is published.

## Dashboard records are missing

Confirm that you are in the intended organization, team, and project, then check **Issues**, **Errors**, or the project ANR route as appropriate. Filters can hide items; reset or adjust the project **Issues** filters before assuming ingestion failed.
