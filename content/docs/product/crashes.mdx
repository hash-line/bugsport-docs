## What BugsPort records

The reviewed REST contract accepts crash reports at `POST /v1/projects/{projectId}/crashes`. It accepts a non-empty JSON Patch body and also declares a multipart form with `crash_record` and `breadcrumbs` parts. A successful response identifies the crash and reports whether it is known and whether a sample was stored.

In the dashboard, **Errors** groups crash occurrences. A selected occurrence can show its stack trace, breadcrumbs, and occurrence information when those fields are present.

## Send a verified report

The currently published Android integration does not expose a completed public first-issue method. Use the [REST API integration guide](/api) to validate a project-scoped request before creating a real issue. The generated [crash endpoint reference](/api/reference/v1/projects/projectid/crashes/post) is the contract source for crash request shapes.

## Diagnose an occurrence

1. Open the project’s **Errors** view.
2. Choose a crash group, then an occurrence.
3. Review the stack trace and breadcrumbs that are present for that occurrence.
4. Use the [issue triage workflow](/product/issue-triage) when the crash should be tracked as an issue.
