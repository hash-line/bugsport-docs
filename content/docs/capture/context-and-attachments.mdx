## Context visible in issue detail

Current issue detail can display app, build, user, operating-system, device, environment, release, stack-trace, navigation-trace, breadcrumb, attachment, and network-request sections when the issue contains those values. Their presence depends on the submitted record; this is not a promise that every integration captures them automatically.

## Attachments

The reviewed contract provides `POST /v1/projects/{projectId}/attachments` with a multipart `file` field. Attachment responses include an ID, project ID, filename, content type, size, and optionally URLs and associated issue IDs. The endpoint reference is the source of truth for request and response details.

Use a project-scoped `x-api-key` for the request. The current contract also exposes issue relations and attachment links; use the generated [attachment reference](/docs/reference/api/v1/projects/projectid/attachments/post) and [issue reference](/docs/reference/api/v1/projects/projectid/issues/id/patch) rather than guessing a linking payload.
